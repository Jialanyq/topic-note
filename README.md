# topic-note

A WorkBuddy skill that turns pasted copy into an archived, structured Chinese research note: preserve every fact, verify and enrich from first-hand sources, restructure by logic, strip AI-writing patterns, optimize title / lede / closing with a 5-judge panel, then save to `~/Documents/TOPICS/YYYY-MM-DD_keyword.md`.

把一段粘贴进来的文案，整理成一篇结构清楚、可长期归档的中文研究笔记。

---

## 它解决什么问题

把长文整理成笔记，最容易出四个毛病，这个 skill 逐条堵住：

**内容写丢。** 摘要式改写会把数字、口径声明、来源引用吃掉。这里定了"只增不减"：原文每个事实都必须在新稿里落地，允许改顺序、改句式、合并段落，不允许丢。

**结构照搬导致重复。** 原稿往往按"观察维度"组织，同一件事在三个章节里各说一遍。这里改成按逻辑重排，同一份清单只出现一次。

**AI 味重。** 破折号过密、加粗小标题泛滥、"这正是关键"这类自我提示语、三段并列。这里给了一份中文场景的清理清单，分必删、降级、拆分、保留四档。

**命名混乱。** 固定成 `YYYY-MM-DD_主体英文或拼音_中文短语.md`，同日同主体覆盖，不新建副本。

## 五条硬约束

1. **只增不减**：原文的每个事实、数字、判断、口径声明都要落地
2. **不用表格**：房型、参数、对比、评分这些天然适合表格的内容，一律写成句子
3. **不留摘抄痕迹**：正文与附录都不出现期数、短讯、系列、原文这类指向连载或摘录的表述，也不出现第一人称媒体自称
4. **风格贴着原文**：去 AI 味只做减法，原文的特征句式保留几处
5. **路径与命名固定**：`~/Documents/TOPICS/YYYY-MM-DD_关键词.md`

## 工作流

八步，顺序不能换：

1. **建事实清单** —— 逐句过原文，抽出事实与数字、作者判断、来源引用、口径声明四类，形成清单，后续对着清单核销
2. **核验与补料** —— 一手来源优先（官网、新闻稿、获奖名单、设计事务所、IR 资料），新增内容必须能说清来源，与原文冲突时保留原文另加口径说明
3. **结构重排** —— 按"事实 / 产品 / 在地性 / 商业 / 判断 / 参照系"重排，去重是核心
4. **去 AI 味（轻量）** —— 读 `references/style-guide.md`，只做拆破折号、降标题、删自我提示语三类动作
5. **变体优化** —— 标题、导语、结尾各出 10 个变体，5 人评审团（CMO / 怀疑派创始人 / 转化优化师 / 资深文案 / CEO）各打 0 到 100 取平均，三项拼成整篇后做组合校验，85 分以上可用
6. **排版** —— YAML front-matter 只写 title / date / tags / skills，二级标题用"一二三"编号，单段不超过五行
7. **自检** —— 跑三条 grep 命令查表格残留、痕迹词残留、章节结构
8. **交付** —— 打开成品，用三句话说明结构怎么调的、补了什么、得分多少

## 安装

```bash
git clone https://github.com/<your-username>/topic-note.git ~/.workbuddy-ai/skills/topic-note
```

或者把 `SKILL.md` 和 `references/` 手动拷到 `~/.workbuddy-ai/skills/topic-note/`。

装好后在 WorkBuddy 里粘贴文案，说"整理成笔记""存到 TOPICS""去 AI 味再存"就会触发。

## 目录

```
topic-note/
├── SKILL.md                    # 五条硬约束 + 八步流程 + 常见返工原因
└── references/
    └── style-guide.md          # 中文去 AI 味清单、结构模板、自检命令
```

## style-guide 里有什么

通用的去 AI 味规则大多是英文语境（em dash 密度、rule of three、copula avoidance），搬到中文里不成立。这份文件把中文场景的痕迹换成了具体项：

**必删** —— 自我提示语（这正是关键、值得注意的是）、意义通胀（标志着、折射出、彰显了）、空洞总结段、模糊引证（业内人士认为）、协作腔（希望这份整理对你有帮助）

**降级** —— 加粗的行内小标题改为三级标题，加粗只留给术语

**拆分** —— 破折号一篇超过六次就拆、长句三个逗号分层就断、三段并列改两项或四项

**保留** —— "不是 X，而是 Y"的对偶句式、第一人称判断、不完整的想法与插入语、行业黑话

末尾附三条自检命令，第一条必须输出 0，第二条必须无匹配。

## 设计取舍

**为什么坚持不用表格。** 表格会诱导作者把内容切成等长的碎片，写出来像规格书而不是笔记。改成叙述之后，房型、参数、评分这些信息反而更容易读出因果关系。

**为什么保留对偶句式。** "不是 X，而是 Y"在中文评论写作里是常见修辞，全删会显得不像人写的。skill 里明确写了保留几处，这是刻意的。

**为什么强调一手来源。** 二手转述里的数字常常没有日期、没有口径。skill 要求三类口径分开标注（平台口径 / 现场观察口径 / 集团口径），未标日期的第三方数字不采用。

## 已知限制

- 归档路径写死为 `~/Documents/TOPICS/`，换目录要改 SKILL.md 第 5 条
- 自检命令是 grep，Windows 环境需要换成 PowerShell 的 `Select-String`
- 变体优化用模拟评审团打分，不接真实流量，适合发布前的初筛，不能替代 A/B 测试
